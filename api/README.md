# Recipe API (static, read-only)

254 recipes as static JSON, meant for GitHub Pages (or any static host). The import was a one-time job;
everything except `api/recipes/` and `api/catalog.json` is generated by `tools/build-index.mjs`.

## Layout

    api/version.json            content hash; fetch with cache: 'no-store' to detect updates
    api/index.json              one entry per recipe for list + search:
                                id, slug, title, category, categorySlug, subcategory, tags, servings, ingredients (names)
                                need (catalog ids of required ingredients: not optional, shop !== false)
    api/recipes/<slug>.json     full recipe (schema: api/recipe.schema.json)
    api/catalog.json            { items: [{ id, name, aisle, staple }] }, the ingredient catalog
    api/categories/index.json   [{ slug, name, count }]
    api/categories/<slug>.json  { slug, name, recipes: [{ id, slug, title, subcategory }] }
    api/tags/index.json         [{ tag, count }]
    api/tags/<tag>.json         { tag, recipes: [...] }
    ../REVIEW.md                import notes: items to verify against the original files (not part of the API)

Size: about 2 MB of JSON in total (the index is about 125 KB); GitHub Pages serves it gzipped.

## Identifiers

- `id` is an immutable UUID. Key cook notes, favorites and shopping lists on it in IndexedDB.
- `slug` is the URL/file name and can be corrected later without breaking user data.

## Shopping lists

Each ingredient has `catalogId` and `amount` ({ value, unit } where unit is g, ml, each or pkg).
To merge lines across recipes, sum `amount.value` grouped by `catalogId` + `amount.unit`; show mixed units as separate
lines. `catalog.json` gives each id its display name, grocery aisle and a `staple` flag (salt, oil, etc.).
Skip lines with `shop: false`. Lines with `confidence: "low"` are best shown with their `raw` text.
Ingredients with `amount: null` (to taste, a few dashes) have no total; list them once without a quantity.

## Tags and categories

`category` comes from the original folder. The 32 recipes from the KETO RECIPES subfolder also carry the tag `keto`.
The tag `main` marks dinner entrées that the meal planner may choose (110 recipes, picked by hand).
Other tags can be added to a recipe file by hand.

## Editing

1. Edit or add `api/recipes/<slug>.json` (new recipes need a new UUID `id` and `catalogId`s that exist in `catalog.json`).
2. Run `node tools/build-index.mjs` (Node 18+). It validates the recipes and rebuilds the index, categories, tags and version.
3. Commit and push. `.nojekyll` is included so GitHub Pages serves the files as-is.

The recipes were converted once from the parsed archive (`recipes_all.json`, not in this repo) by
`tools/convert-parsed.mjs`. That tool was removed because re-running it would overwrite every hand edit, such as
the `main` tags; it is in the git history if the archive ever needs converting again.

## Not in this API

Ratings, notes, plans and the pantry are per-device data (IndexedDB), keyed by recipe `id`.

The recipes are a private family collection; some come from published sources and remain theirs. They are not
covered by the code license (see `../LICENSE`).
